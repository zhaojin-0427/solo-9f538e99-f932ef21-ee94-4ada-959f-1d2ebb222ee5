# 共享电单车电池寿命分析

用 Flask + SQLite 做的电池随访台账与 Kaplan–Meier 无故障概率页面，按机龄帮助车队安排抽检。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>（可用 `APP_PORT` 改端口）。数据库保存在 `battery-data` 卷中，
容器以非 root 用户运行并带健康检查。

本地开发：

```bash
python3 -m pip install -r requirements.txt
python3 app.py            # 或 BATTERY_DB=/tmp/x.db python3 app.py
python3 -m pytest tests -q
```

## 使用流程

1. 在 **上传随访** 页提交 CSV（UTF-8 或 GB18030；可先下载模板）。
2. 在 **寿命分析** 页选择截止日（UTC），查看每个发生过故障的机龄对应的在险数、故障数
   和 KM 无故障概率。
3. **台账** 页查看当前生效的每块电池记录；当台账电池数与寿命汇总对不上时，可在该页
   点击 **校准汇总**，按现有分组口径把寿命汇总修正回与台账一致。

### CSV 格式

必需列（也接受对应中文表头）：

| 列 | 含义 |
| --- | --- |
| `battery_no` | 电池号，文件内必须唯一 |
| `activation_date` | 启用日（UTC，`YYYY-MM-DD`） |
| `followup_start` | 随访首日 |
| `followup_end` | 随访末日 |
| `outcome` | `failure` / `censored`（也接受“故障 / 正常结束”） |

可选 `action` 列：`insert` / `update` / `delete`（或“补录 / 更正 / 删除”）。
留空时自动判断：新电池号新增，已存在则视为更正（同号旧记录被覆盖）。

日期接受 `YYYY-MM-DD`、`YYYY/MM/DD`、ISO 8601 时间戳；带时区的时间会先换算为 UTC 再取日期。

### 校验规则

* 整份文件先校验再写入；任一行出错则整份拒绝，数据库和已有曲线都不受影响。
* 同一文件内电池号重复、日期缺失/非法、随访首日晚于末日、随访末日早于首日都会报错并给出行号。
* 同一电池号的更正覆盖旧值，删除则从曲线中移除。

## 统计口径

* 机龄 = 随访日期 − 启用日，按整天计算。
* 随访截到所选截止日：尚未入组的电池（随访首日晚于截止日）不计；
  截止当天发生的故障照计；截止当天结束随访的电池仍计入当天在险数。
* 同一机龄先入组再计故障；某机龄当天结束时先计入在险数再删失。
* 截止日后的故障按该日删失处理。
* KM 无故障概率逐故障机龄相乘：`S(t) = ∏ (1 − d_i / n_i)`，只列出发生故障的机龄。

## 存储结构

| 表 | 用途 |
| --- | --- |
| `battery_ledger` | 台账：每块电池当前一条记录 |
| `battery_summary` | 每块电池 1 条汇总记录（更正原地覆盖并递增 `revision`） |
| `battery_summary_usage` | 每块电池汇总记录的终身用量，补录/更正/删除各计 1 次，上限 6 条 |
| `summary_counts` | 按启用日与天偏移预聚合的计数，**分析页只读这张表** |
| `import_batches` | 导入批次统计 |
| `ledger_changes` | 每次台账写入的追加式审计（校准的扫描水位依据） |
| `calibration_runs` / `calibration_group_changes` / `calibration_battery_changes` | 校准批次及每个修正分组的前后计数 |

每块电池的补录、更正、删除合计最多写入 6 条汇总记录；超出时整份文件被拒绝，
已有曲线不受影响。台账、汇总记录、用量计数和聚合计数在同一个 SQLite 事务中写入；
导入失败整体回滚，分析页仍可按原有汇总计数查询（即使台账表本身不可用也不影响曲线）。

## 校准汇总

在 **台账** 页点击「校准汇总」（`POST /calibrate`）即可把 `summary_counts` 与
`battery_summary` 按当前台账重新对齐：

* 沿用现有的「启用日 + 入组/结束机龄 + 结局」分组口径，**只改写计数不符的组**；
  页面列出每个修正分组的校准前/后计数，任一侧原本没有该组时按 0 计（台账侧为 0
  则删除多余汇总行，汇总侧为 0 则补插缺失行）。
* 一次校准最多全扫台账一遍。扫描阶段只读、不持写锁，随访导入照常提交；随后在一个
  短写事务里只按主键回读扫描期间变动过的电池，把它们的最新台账状态（含扫描开始后
  入账的补录、更正、删除）并入校准口径。
* 校准在单个事务内提交，因此寿命页每次查询读到的要么是校准前、要么是校准后的整套
  计数，不会读到半新半旧的中间状态。
* 校准过程中任何错误都会撤销本次全部修正；此前已提交的导入不受影响、照常保留。
* 校准不写 `battery_summary_usage`，不占用每块电池 6 条汇总记录的额度；校准完成后
  还会做一次复核，复核不过同样整体回滚。
* 寿命分析页保持只读汇总，页面上没有任何校准入口。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/survival?cutoff=YYYY-MM-DD` | 寿命分析页（只读汇总） |
| GET/POST | `/upload` | 上传页面 / 导入 CSV |
| GET | `/ledger` | 当前台账、两侧电池数与校准历史 |
| POST | `/calibrate` | 按台账校准寿命汇总，返回每个修正分组的前后计数 |
| GET | `/template.csv` | 下载模板 |
| GET | `/healthz` | 健康检查 |
